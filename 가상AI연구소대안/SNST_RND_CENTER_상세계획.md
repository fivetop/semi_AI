# SNST RND CENTER 상세 계획

전체 구성원 14명의 업무 정의, AI 에이전트, 프로세스, 프로젝트를 정리함.

---

## 1. 구성원 상세 업무 정의

### 1.1 전략 기획팀 (3명)

| 직책 | 이름 | 상세 업무 |
|------|------|----------|
| **팀장** | - | 연구소 전체 방향 수립, 연간 예산 계획, 외부 파트너십 확보, 투자 유치 활동 |
| **기획팀장** | - | 분기별 프로젝트 계획 수립, 일정 관리, 리소스 배분, 고객사 요구사항 정리 |
| **분석가** | - | 시장 조사 (반도체 AI 트렌드), 경쟁사 분석, 기술 동향 리포트 작성 |

### 1.2 기술 연구팀 (7명)

| 직책 | 이름 | 상세 업무 |
|------|------|----------|
| **연구소장** | - | 기술 로드맵 수립, AI 모델 선정, 연구 방향 결정, 품질 검토 |
| **수석 연구원** | - | 아키텍처 설계, 프롬프트 템플릿 개발, 기술 벤치마크 설정 |
| **연구원 1** | - | RTL 생성 프롬프트 개발 (Verilog/SystemVerilog) |
| **연구원 2** | - | 검증 프롬프트 개발 (Testbench, Assertion) |
| **연구원 3** | - | PPA 최적화 프롬프트 (Power, Performance, Area) |
| **연구론 4** | - | PNR 프롬프트 개발 (Floorplanning, Placement, Routing) |
| **연구론 5** | - | 디버깅 및 수정 프롬프트, 문서화 |

| 직책 | 이름 | 상세 업무 |
|------|------|----------|

## 2. AI 에이전트 구성

### 2.1 연구소장 AI (Director AI)

```
역할: 전략 의사결정, 연구 방향 결정
모델: Qwen2.5-14B 또는 Llama3-70B
업무:
  - 연구 과제 평가 및 우선순위 결정
  - 기술 방향 제시
  - 팀 성과 리뷰
```

### 2.2 RTL 엔지니어 AI (RTL Engineer AI)

```
역할: RTL 코드 생성
모델: Qwen2.5-7B + 도메인 프롬프트
업무:
  - SystemVerilog 코드 생성
  - 스keleleton 코드 보완
  - 명세서에서 RTL 변환
```

### 2.3 검증 엔지니어 AI (Verification Engineer AI)

```
역할: 검증 자동화
모델: Qwen2.5-7B + 검증 프롬프트
업무:
  - 테스트 벤치 생성
  - assertion 작성
  - 커버리지 분석
```

### 2.4 PNR 엔지니어 AI (PNR Engineer AI)

```
역할: 배치 배선 최적화
모델: Qwen2.5-7B + PNR 프롬프트
업무:
  - Floorplanning 제안
  - 배치 가이드라인 생성
  - 타이밍 최적화 조언
```

### 2.5 QA 엔지니어 AI (QA Engineer AI)

```
역할: 품질 검토
모델: Qwen2.5-7B
업무:
  - 코드 리뷰
  - 버그 발견
  - 최적화 제안
```

### 2.6 문서화 AI (Documentation AI)

```
역할: 기술 문서 작성
모델: Qwen2.5-7B
업무:
  - 설계 문서 작성
  - 테스트 리포트 정리
  - 사용자 매뉴얼 작성
```

## 3. 업무 프로세스 설계

### 3.1 일상 업무 흐름

```
┌─────────────────────────────────────────────────────────────┐
│                    일일 업무 흐름 (Daily Flow)              │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  09:00  │ 팀 미팅 (업데이트 공유, 오늘 할 일 확인)          │
│         ▼                                                    │
│  09:30  │ AI 에이전트 작업 시작                              │
│         │ - RTL/검증/PNR 프롬프트 실행                       │
│         ▼                                                    │
│  12:00  │ 점심 식사                                         │
│         ▼                                                    │
│  13:00  │ 오후 업무                                        │
│         │ - 결과 검토 및 개선                               │
│         │ - 고객 미팅 (해당 시)                            │
│         ▼                                                    │
│  17:00  │ 일일 리포트 작성                                   │
│         │ - 작업 결과, 이슈, 다음 날 할 일                  │
│         ▼                                                    │
│  17:30  │ 팀 리뷰 (필요시)                                  │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 프로젝트 진행 프로세스

```
프로젝트 시작
     │
     ▼
┌─────────────┐
│ 1. 분석    │ ← 고객 요구사항 분석
└──────┬──────┘
       │
       ▼
┌─────────────┐
│ 2. 계획    │ ← 일정, 리소스 계획
└──────┬──────┘
       │
       ▼
┌─────────────┐
│ 3. 설계    │ ← AI 프롬프트 설계
└──────┬──────┘
       │
       ▼
┌─────────────┐
│ 4. 개발    │ ← AI 에이전트 실행
└──────┬──────┘
       │
       ▼
┌─────────────┐
│ 5. 검증    │ ← 결과 검증, QA
└──────┬──────┘
       │
       ▼
┌─────────────┐
│ 6. 완료    │ ← 최종 결과 전달
└─────────────┘
```

### 3.3 품질 관리 프로세스

```
AI 결과 생성
     │
     ▼ 자동 검사
     │
     ▼ 수동 리뷰 (연구원이 확인)
     │
     ├── 문제 발견 → 수정 요청 → 다시 생성
     │
     └── 통과 → 최종 결과
```

## 4. 프로젝트 계획

### 4.1 1차 프로젝트 (1~3개월)

| 프로젝트 | 내용 | 기간 |
|----------|------|------|
| **프롬프트 라이브러리 구축** | RTL, 검증, PNR용 프롬프트 템플릿 모음 | 2개월 |
| **AI 테스트 벤치 생성기** | 자동 테스트 벤치 생성 도구 | 3개월 |

### 4.2 2차 프로젝트 (4~6개월)

| 프로젝트 | 내용 | 기간 |
|----------|------|------|
| **RTL 생성 자동화** | 명세서에서 RTL 자동 생성 | 3개월 |
| **PPA 최적화 도구** | 전력, 성능, 면적 최적화 조언 도구 | 3개월 |

### 4.3 3차 프로젝트 (7~12개월)

| 프로젝트 | 내용 | 기간 |
|----------|------|------|
| **전체 설계 자동화 파이프라인** | RTL부터 PNR까지 End-to-End 자동화 | 6개월 |
| **고객 데모 개발** | 실제 고객 과제 데모 | 3개월 |

### 4.4 연간 목표

| 목표 | 내용 |
|------|------|
| **기술 완성도** | 10개 이상 프롬프트 템플릿 완성 |
| **고객 확보** | 3개 이상 파트너십 계약 |
| **실적** | 2개 이상 프로젝트 완료 |
